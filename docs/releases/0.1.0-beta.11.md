# Meshy Torrent 0.1.0-beta.11

Security and reliability improvements for log handling, network connections, and
local data storage. No new user-facing features.

## Changes

- Added log redaction: URLs, tracker addresses, passkeys, tokens, base64 torrent
  data, binary buffers, and error messages containing sensitive fields are now
  scrubbed before reaching the application log, reducing the risk of credential
  or metadata exposure in log files.
- Added a network policy for tracker and web-seed connections: DNS responses
  resolving to private, loopback, or link-local addresses are blocked before the
  connection is established, preventing server-side request forgery via crafted
  announce URLs.
- Added URL validation to the announce list, extension sources (`xs`), and
  `addWebSeed` calls: non-HTTP(S) web-seed sources and malformed tracker URLs
  are dropped at the point of use, not just at add time.
- Replaced the plain `electron-store` instance with a protected store backed by
  the system key store (`safeStorage`). Storage errors (key store unavailable,
  unreadable credentials, write failure) now show a translated error dialog
  instead of silently failing, with the existing data files preserved in all
  cases.
- Added `ipaddr.js` and `node-fetch` as direct runtime dependencies (previously
  transitive); both are now used in the network policy and HTTP transport layer.

## Installation and update

Use Check for updates in the app, or download the Windows x64 installer from this
release. The installer, blockmap, update manifest, and SHA-256 checksums are
included.

## Known issues

This beta is distributed without an Authenticode signature. Windows may show an
unknown publisher warning during installation. Local TCP transfer and isolated
renderer/preload checks do not replace clean-machine installation testing.
