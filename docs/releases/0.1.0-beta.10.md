# Meshy Torrent 0.1.0-beta.10

Reliability and correctness fixes for torrent removal, seeding control, and
settings persistence.

## Changes

- Fixed torrent removal leaving a broken in-memory state when file deletion fails:
  the download now transitions to an error state and the torrent is paused so data
  is not lost. The file catalog and metadata are saved before the operation begins
  so a retry is possible even after restarting the app.
- Fixed a race condition where concurrent operations could run against a torrent
  while it was being removed; a guard now blocks pause, resume, retry, and seeding
  changes for the duration of the removal.
- Fixed the seeding toggle being non-idempotent: the IPC command
  (`torrent:set-seeding-enabled`) now receives an explicit `enabled` boolean, so
  a retry after a transient failure cannot accidentally flip the seeding state.
- Fixed multiple settings changes being written as separate store operations; they
  are now committed in a single atomic write, eliminating a window where a crash
  could leave settings in a partially-updated state.
- Fixed file deletion on torrent removal not re-validating path containment
  immediately before each `unlink`; containment and symlink checks are now
  performed per-file at deletion time.

## Installation and update

Use Check for updates in the app, or download the Windows x64 installer from this
release. The installer, blockmap, update manifest, and SHA-256 checksums are
included.

## Known issues

This beta is distributed without an Authenticode signature. Windows may show an
unknown publisher warning during installation. Local TCP transfer and isolated
renderer/preload checks do not replace clean-machine installation testing.
